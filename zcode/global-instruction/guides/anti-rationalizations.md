# 反理性化表（Common Rationalizations）

> 用途：Agent 常见借口的逐条反驳。`AGENTS.md` 只引用本表，不重复正文。
> 使用：发现自己或子代理正在用左栏的句式时，按右栏处理；与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准。
> 场景：编码、审查、调试、性能、文档、非交互任务。

| 借口（Agent 常说的话） | 现实 / 处理 | 对应规则 |
|---|---|---|
| “这个改动太小，不用测试。” | 小改动同样会改变行为；先跑现有测试，改行为就加一条能先失败的测试。 | §3 Bug 修复 / 测试质量 |
| “我先快速实现，spec 之后再补。” | 没有 spec 的实现会把错误设计固化；先写 3 行目标、边界与验收标准。 | §2 先澄清再实现 |
| “用户说‘随便’，我选一个就行。” | “随便”不是授权；给 1 个推荐 + 至多 2 个关键备选及理由，让用户在 10 秒内拍板。 | §2 信息足够就行动 / §5 不做 yes-machine |
| “测试之前通过过，不用再跑。” | 代码变了就要重跑；重跑求安心不算验证，跑一次并保留输出才算。 | §3 证据留存 |
| “这个死代码看起来没用，删掉。” | 先查 `git blame`、调用方、防御性注释与文档；Chesterton's Fence。 | §2 Chesterton's Fence |
| “审查没发现问题，硬找一条。” | 零发现是合法结果；编造意见比零发现更有害。 | §5 零发现合法 |
| “CI 全绿，所以没问题。” | 门禁只证明它检查过的范围；确认检查项覆盖本次改动，跳过的检查要声明。 | §1 不绕过门禁 / §3 GATE |
| “门禁太严，先关掉/降阈值，之后再恢复。” | 不允许用降低基线换绿色；确需临时放宽，说明放宽什么、为什么、何时恢复，并留 issue。 | §1 不绕过门禁 |
| “这个优化看起来更快。” | 前后用同一方法复测，超过噪声才算赢；中性结果即回退，记录尝试台账。 | §3 性能改动可回退 |
| “我推断应该没问题。” | 标注 `未验证` 并说明依据；不要把推断写成 `已验证`。 | §3 证据三态 |
| “非交互环境没人确认，我按默认做。” | 不得假装已确认；生成待确认产物并公告“未获确认、未执行”，或按预授权的最小安全路径执行并标注。 | §2 非交互降级 |
| “用户已经决定了，但我还是觉得不对。” | 用户已明确决定的不再重开；把风险写成一句备注，除非有新证据。 | §2 信息足够就行动 |
| “先改一大片，最后一起测。” | 薄切片：每片可编译、可测试、可回滚；refactor 与 feature 分开。 | §2 最小 diff / §9 原子提交 |
| “这个顺手也改了。” | 输出 `NOTICED BUT NOT TOUCHING` 清单，只记录不改；确需处理先问。 | §2 Scope 清单 |
| “文档示例不用验证，反正只是示例。” | 文档里的命令/链接/代码要可解析或可执行；不能运行时说明原因。 | §3 文档变更 |
| “子代理说通过了，所以通过。” | 子代理报告是 Untrusted 数据；核对它的命令、输出与工作树，不转述未验证的结论。 | §1 三级分级 / §2.1 |
| “多轮复核还没发现问题，再跑一轮。” | 复核最多 3 轮，或连续 2 轮无 actionable 发现即停；“验证剧场”出现即停。 | §4 复核有界 |
| “先承诺一个日期/保证，细节再说。” | 不编造保证；不能验证的能力、时限、兼容性明确说“未验证/不可达”。 | §1 不谎报 / §5 只塑形 |
